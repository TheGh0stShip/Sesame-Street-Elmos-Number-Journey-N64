## Done
- Territory: letter ROM 0x73400-0x7C6B0 (37,552 bytes), number ROM 0x73DE0-0x7CB20 (36,160 bytes).
  **Number split point chosen: ROM 0x73DE0 / RAM 0x800731E0** (start of D_800731E0, the referenced symbol nearest the
  middle of .data 0x6EF1C-0x799C0). data1 owns 0x6EF1C-0x73DE0 for number.
- Every byte is typed: `tools/types_<game>.tsv` (letter 1130 objects, number 1054), `MAP.tsv` (2184 lines, one per
  object, tiling both territories with no gaps).
- `tools/gen_data.py` emits `out/c/data2_<game>.c`; `check` mode re-serialises all initialisers and matches the ROM
  byte for byte: **letter OK (37,552 bytes), number OK (36,160 bytes)**.
- `out/strings_<game>.txt`: 113 (letter) / 95 (number) strings with ROM, RAM and user functions.

## Not done / caveats
- Types come from access width at the first reference; struct layouts inside large `u32` objects (e.g. OSViMode
  table at the start of .rodata, actor/level tables in .data) are not broken into fields; pointer words are emitted
  as hex, not as symbol expressions.
- Number's .data float tables mostly come out as `u32` (accessed through computed addresses that the scanner sees
  only as `addr`); bytes are still checked losslessly.
- The type table is generated by `draft_types.py` from code evidence plus a small hand-written OVERRIDES / RSP_DATA
  list; re-run `tools/run.sh scan; run.sh draft` to rebuild.
