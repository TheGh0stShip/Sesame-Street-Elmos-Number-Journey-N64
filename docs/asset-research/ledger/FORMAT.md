# ledger: merged byte ledger of both ROMs (format and priority rules)

Generated by `tools/merge_ledger.py OUTDIR [--rom letter=PATH] [--rom number=PATH]` (driver: `tools/run.sh`, run
through job.sh). Inputs: every `sesassets/*/MAP.tsv`, `sestools/functions.json` + `sesverify/v16/<game>/VERIFY.tsv`
(code), and the sizes of the inflated level images `lvlA/out/<game>/*.bif.bin`. The ROMs and the inflated images
are read only to test whether a range nobody claims is all zero. No ROM bytes are written anywhere.

## Files
| file | content |
|---|---|
| `LEDGER_<game>.tsv` | one tiling of ROM 0x000000-0x800000: no gaps, no overlaps (asserted) |
| `LEVELS_<game>.tsv` | the same for each of the 8 inflated level images (offsets inside the image; col 1 = file) |
| `CONFLICTS_<game>.tsv` | every pair of overlapping claims from two agents that disagree (see below) |
| `SUMMARY.md` | bytes per kind and per owner (ROM, each level image, all levels), conflict counts, every unknown range, the cut/unused list |

## Columns (LEDGER; LEVELS has `file` first)
1. `start`, 2. `end` (exclusive, hex). 3. `class`: the owner's own class name. 4. `format`, 5. `description`: the
owner's text. If the ledger row is only part of the owner's row (a higher-priority claim cut it) the description ends
with `[part A-B of <agent> row X-Y]`. 6. `owner`: agent folder (`code` = functions.json / sesverify v16, `none` = no
map claims it). 7. `extractor`: the owner's extractor, prefixed with its folder. 8. `kind`: normalised class used
for totals and conflict tests. 9. `reference`: the owner's "referenced by" column.

Kinds: texture, palette, display_list, vertex, vertex_list (rebuild / dup / vertex-order lists), model_header, bbox,
morph_anim, collision (quads, BSP, tris), level_object, song, audio_bank, speech, program_data (.data/.rodata
scalars, tables, strings, doubles), rsp, code, header, boot, elf_comment, container, pad, unknown
(`unknown` and `level_data` both map to unknown). The mapping table is `KIND` in the script; agent-specific cases:
audio's `audio` = audio_bank, speech's `audio` rows = song (libmus format) or speech, packC `table` = vertex_list,
every non-pad `files` row = container.

## Priority rules (who owns a byte)
Every claim is painted onto the space in increasing priority; the last painter owns the byte. Priority is
(tier, agent rank, smaller row wins within one agent).

Tiers:
- -1: containers other than gzip members (`files` rows, gfx `container` rows): any content claim wins (contents over containers).
- 0: `unknown` / `level_data` claims: lose to any identified claim of any agent (an unknown from a dedicated agent
  does not hide a real identification by gfx).
- 1: all identified claims, including `pad`.
- 2: lvlA `gzip_level` rows: a compressed level member is ONE ROM row owned by lvlA whose description points to
  `LEVELS_<game>.tsv file=<name>.bif`.

Agent rank in ROM (higher wins): files 10 < gfx 20 < code 25 < data2 30 < data1 31 < speech 40 < packC 41 < audio 50
< packA = packB = sprA 60 < songs 61 < lvlD 62 (its .data pointer tables) < ucode 70 < hud 75 < lvlA 90.
Reasons: gfx only where no dedicated agent covers the bytes; data1 keeps the whole texture D_80072160 across the
data1/data2 split; code (functions.json) loses the 20-byte `.data` island 0x103C-0x1050 that func_80000400's size
runs into; songs own song files (over speech's and audio's copies), audio owns pointer/wave banks (over speech's
8-byte "tail" at 0x4D9D78); ucode owns the RSP blocks data1/data2 kept as words; hud corrects packC; lvlD's typed
pointer tables refine data1/data2.

Agent rank in level images: gfx 20 < lvlB 30 < lvlC 40 < lvlE = lvlF = lvlG = lvlH 60 < lvlD 65. lvlB's
`level_data` is tier 0, so every other agent wins there; lvlD-H win over lvlB's 0x24-byte model headers. lvlD is
above lvlE-H because it describes whole objects (the full 0x28-byte mesh header, whole morph animations), while
lvlE-H filled only what lvlB/lvlC left (e.g. a 4-byte `model_header_tail`).

Bytes no map claims become `owner none`: class `pad` if the ROM/image bytes there are all zero, else `unknown`
(there are none in the current run).

## CONFLICTS columns
`space` (ROM or level file), `overlap_start/end`, `type` (`class`: same bounds, different kind; `boundary`: same
kind, different bounds; `class+boundary`), then for each claim: agent, start, end, class, kind, description
(160 chars), and `ledger_owner` (owner(s) of the overlap in the ledger).
Not counted as conflicts (counts in SUMMARY.md): container/content nesting (content fully inside a container row),
unknown-vs-identified, and identical claims (same kind and bounds).
