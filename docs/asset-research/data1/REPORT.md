# data1 report (first half of program `.data` + the entry `.data` island, both games)

## Territory and split
| game | piece | RAM | ROM | bytes |
|---|---|---|---|---|
| both | entry-object `.data` island | 0x8000043C-0x80000450 | 0x103C-0x1050 | 20 (all zero: pad) |
| letter | `.data` first half | 0x8006C9AC-0x80073160 | 0x6D5AC-0x73D60 | 26548 |
| number | `.data` first half | 0x8006E31C-0x800741E0 | 0x6EF1C-0x74DE0 | 24260 |

**Split note (data2 please read):** the brief's letter boundary ROM 0x73400 (RAM 0x80072800) falls inside
the 4 KB texture D_80072160 (0x80072160-0x80073160). I kept that object whole, so letter data1 ends at
**ROM 0x73D60 / RAM 0x80073160**. For number I split at the end of the same twin texture
(D_800731E0, 0x800731E0-0x800741E0): **ROM 0x74DE0 / RAM 0x800741E0** (the next referenced object is
0x800741E0, used by func_8000F8D8). data2 should start at those addresses.

## Done
Every byte of both territories is in MAP.tsv (224 objects) with a C type; `gen_data.py check` passes for
both games (letter 110 objects / 26568 bytes, number 115 / 24280 bytes, exact match, exact tiling).

Tools (all take the ROM path; none contains ROM content):
- `tools/gen_data.py ROM GAME OUTDIR` / `gen_data.py check ROM GAME OUTDIR` - emitter and lossless check.
- `tools/types_letter.tsv` (hand-written), `tools/types_number.tsv` (generated by `mk_number_types.py`).
- `tools/refs.py` - disassembles every matched function and lists each %hi/%lo reference and data pointer
  into a RAM range with access width (this, not the D_ names, is the object-start source; see oddities).
- `tools/survey.py` - D_ symbol / extern-type survey of the matched sources. `tools/run_refs.sh`,
  `tools/run_gen.sh` - runner wrappers. Outputs in `out/` (data1_<game>.c, MAP_<game>.tsv, refs).

## Not done / limits
- The emitted C is checked by re-serialisation, not compiled; definitions are in address order but a real
  link would also need the section placed at the .data start (the RSP tail must stay first).
- The rsp_ucode block is kept as raw words; decoding/identification belongs to the ucode agent.
- TexPair values are heap RAM addresses of loaded assets, written as hex (no symbol exists for them).
- Field names inside user structs (TexPair, FontDesc, NodeList) are inferred; FontDesc order was confirmed by
  the data pointers (chars, glyphs, texture).

## Oddities
- **Number sources use letter-flavoured D_ names in places**: e.g. number func_8000ADBC's source declares
  `D_8006EE6C` while the disassembly references 0x8006FEEC. Object starts for number were therefore taken
  from the disassembly (refs.py), not from the D_ names.
- An orphan one-command display list (gsSPEndDisplayList) at letter 0x800707A0 / number 0x80071820, which
  nothing references.
- An unreferenced pointer to the bss start right after the RSP tail (letter 0x8006D4F0, number 0x8006EE60).
- A complete debug-print kit (8x8 1-bit ASCII font, int*/f64* watch pointers, value slots at 0x80071E40..)
  and a libultra-Sprite text renderer with a frame-timing/lag counter block: development leftovers that
  ship in both games.
- Credits: 130 lines of 40 chars with a per-line colour index table; same layout in both games.
- D_800706D3 (number 0x80071753) is the low byte of the fade alpha word, read with lbu: an alias, not an
  object.
